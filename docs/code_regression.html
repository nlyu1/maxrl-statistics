Code Regression

The code-regression setup asks whether we can predict execution-memory statistics from source code. Our current slice takes the CDSS rows from the Code-Regression dataset and predicts the memory target from the submitted program text. The broader dataset and RegressLM baseline are described in Regression Language Models for Code; our current model family uses T5Gemma encoders and compares supervised regression with rollout-based MaxRL methods from Maximum Likelihood Reinforcement Learning.

Overview

NoteMain thread

This writeup studies scalar CDSS memory prediction from source code. We track two target variants: raw memory_bytes and a per-language quantile-normalized memory score. The experiments then branch into three training routes. CE pretraining follows a RegressLM-style text-to-number recipe and learns one canonical P10 tokenization of the label. LM-RLOO and LM-MaxRL keep the language-model decoder while using sampled token sequences as latent rollouts: each rollout is parsed back to a number and scored against the scalar label. The regression-head route predicts one scalar directly and trains it with SL-MSE, RLOO, or MaxRL. The organizing distinction is between objectives over a token representation and objectives over scalar prediction error.

Problem setup

Each row is a code submission with metadata and a scalar memory target. After preprocessing, we keep only CDSS examples and format the model input as

# CDSS
# Language: Python
<source code>

where Python is replaced by the metadata language when available. The prediction target has two current forms:

  • Raw memory. target = memory_bytes, copied from the original dataset target column after filtering finite CDSS rows.
  • Per-language quantile-normalized memory. Within each CDSS language, raw memory values are ranked and mapped through the standard normal inverse CDF. This keeps ordering inside each language while removing language-specific scale and marginal-shape differences.

Let \(X\) denote the formatted code prompt, \(Y_{\mathrm{raw}}\) the raw memory value, and \(Y_{\mathrm{qn}}\) the quantile-normalized value. In either variant the supervised target is a scalar \[ Y \in \mathbb{R}, \] and the ideal predictor is the conditional mean \[ g^\ast(x) := \mathbb{E}[Y \mid X=x]. \] The main held-out risk is therefore \[ \mathcal{E}(\theta) := \mathbb{E}\left[(g_\theta(X)-Y)^2\right]. \]

The raw target is the literal memory-prediction task. The quantile-normalized target turns the question toward within-language ranking and calibration: can the model place a submission correctly relative to other submissions in the same programming language? Performance on this normalized target should be read as evidence about relative memory behavior inside each language. Raw-byte performance additionally tests whether the model can handle the cross-language unit scale.

Output-side tokenization adds one more layer of notation. Let \[ \mathcal{Z} \] be the finite set of syntactically valid decoder token sequences under the P10 grammar, and let \[ \phi:\mathcal{Z}\to\mathbb{R} \] be the deterministic parser that extracts the numeric value represented by a complete token sequence. A language-model decoder defines a conditional distribution \[ q_\theta(z\mid x),\qquad z\in\mathcal{Z}. \] The latent rollout is the token sequence \(Z\sim q_\theta(\cdot\mid x)\); the decoded prediction candidate is the scalar \(\phi(Z)\).

The targeted regression problem follows the scalar label \(Y\). Token strings enter as one way to produce candidate numeric values. For example, if the final predictor is the median of decoded samples, then the induced predictor is \[ m_\theta(x) := \operatorname{median}\{\phi(Z):Z\sim q_\theta(\cdot\mid x)\}, \] and the corresponding scalar risk is \[ \mathbb{E}\left[(m_\theta(X)-Y)^2\right]. \] Training methods below use different surrogates for this target. Many token sequences can parse to the same number: \[ \mathcal{Z}(v) := \{z\in\mathcal{Z}: \phi(z)=v\} \] can contain several valid strings.

Methods

The current methods combine two related architectures with three objective families. CE pretraining and LM-RL both use an encoder-decoder language model over numeric target tokens. CE learns the canonical token string itself. LM-RLOO and LM-MaxRL sample token strings, parse them to numbers, and optimize scalar reward or likelihood of the parsed value. The regression-head route keeps the T5Gemma encoder idea and predicts through a direct scalar value head, trained with SL-MSE, RLOO, or MaxRL.

CE pretraining - text-to-number language modeling

pretrain_code_regression trains a RegressLM-style conditional decoder. The encoder reads the code prompt, and the decoder autoregressively emits a fixed P10 scientific-notation representation of the scalar target. With the default P10 tokenizer, one number uses

\[ 2 + d = 6 \]

tokens: one sign token, four mantissa digit tokens, and one exponent token. For example, under the default four-digit P10 representation,

256.0   -> <+> <2> <5> <6> <0> <E-1>
-1.25   -> <-> <1> <2> <5> <0> <E-3>
0.1234  -> <+> <1> <2> <3> <4> <E-4>

The table below shows representative raw and quantile-normalized CDSS targets under this P10 tokenization.

The important detail is that training is ordinary language modeling. If \(c(Y) = (Z^c_1,\dots,Z^c_L)\) is the canonical target tokenization of the numeric label, the model minimizes token-level cross entropy \[ \mathcal{L}_{\mathrm{CE}}(\theta) = -\mathbb{E} \left[ \frac{1}{L}\sum_{\ell=1}^{L} \log q_\theta(Z^c_\ell \mid X, Z^c_{<\ell}) \right]. \]

NoteCE learns a numeric spelling

CE pretraining learns a symbolic sign-digit-exponent sequence. Numeric scale enters through the tokenizer’s rounding, clipping, and exponent range, so a single token error can have very different scalar consequences depending on whether it lands in the mantissa or exponent. The digit targets are discrete classes: predicting <6> means assigning probability to the token class <6>. This makes CE a useful RegressLM-style baseline and also makes token likelihood an indirect proxy for numeric MSE.

There is an additional representation issue. The P10 grammar allows valid non-canonical strings with leading zero mantissas, and multiple valid strings can decode to exactly the same number. For example,

<+> <1> <0> <0> <0> <E-3>  -> 1.0
<+> <0> <1> <0> <0> <E-2>  -> 1.0
<+> <0> <0> <1> <0> <E-1>  -> 1.0
<+> <0> <0> <0> <1> <E0>   -> 1.0

CE assigns training mass to the single string selected by the canonicalizer \(c(y)\). Numerically equivalent strings receive no target mass under this CE objective, even though \(\phi(z)\) is correct. When the exact label falls outside the finite P10 grid or between grid points, the canonicalizer first rounds or clips to a representable token string. Thus the CE population target is \[ q^\ast_{\mathrm{CE}}(z\mid x) = \mathbb{P}(c(Y)=z\mid X=x), \] The corresponding set-valued numeric target is \[ \mathcal{Z}(Y)=\{z:\phi(z)=Y\}. \] For deterministic labels and infinite model capacity this distinction can be small, because the canonical string decodes to a good numeric approximation. For finite models it matters: probability mass on a numerically equivalent non-canonical rollout helps scalar prediction while receiving no CE credit.

Decoding is also language-model-like. At each decoder step, impossible P10 tokens are masked out: the first position can only be a sign, middle positions are digits, and the final position is an exponent token. Evaluation samples 64 complete numeric decodes per example and reports the median decoded value before computing scalar metrics.

LM-RL - token rollouts with scalar rewards

LM-RL keeps the same constrained language-model policy as CE and changes the object being optimized. We draw rollout token sequences from the model itself: \[ Z_j \sim q_{\theta,T}(\cdot\mid x),\qquad j=1,\dots,R, \] where \(T>0\) is the sampling temperature used for both sampling and sequence log-probabilities. Each rollout is parsed to a scalar \[ V_j := \phi(Z_j). \] The loss functions then compare \(V_j\) to the exact target value \(y\) stored in the dataset. The learning signal rewards token strings whose extracted number is close to \(y\).

The sequence score used by policy gradients is \[ \log q_{\theta,T}(Z_j\mid x) = \sum_{\ell=1}^L \log q_{\theta,T}(Z_{j,\ell}\mid x,Z_{j,<\ell}), \] with the same P10 validity mask as CE decoding. The sampled scalar values are detached when constructing rewards or score weights; gradients flow through the sequence log-probability.

LM-RLOO

LM-RLOO uses negative squared scalar error as the reward: \[ r_j := -(V_j-y)^2. \] For \(R\geq 2\) rollouts, the leave-one-out advantage is \[ A_j = r_j - \frac{1}{R-1}\sum_{k\ne j} r_k = \frac{R}{R-1}(r_j-\bar r), \qquad \bar r := \frac{1}{R}\sum_{k=1}^R r_k. \] The minibatch surrogate minimized in code is \[ \widehat{\mathcal{L}}_{\mathrm{LM\mbox{-}RLOO}} = -\frac{1}{BR} \sum_{b=1}^B\sum_{j=1}^R A_{b,j}\log q_{\theta,T}(Z_{b,j}\mid x_b), \] where \(A_{b,j}\) is detached. The corresponding population objective is \[ J_{\mathrm{LM\mbox{-}RLOO}}(\theta) = \mathbb{E}_{X,Y} \mathbb{E}_{Z\sim q_{\theta,T}(\cdot\mid X)} \left[-(\phi(Z)-Y)^2\right]. \] Equivalently, LM-RLOO minimizes the expected squared error of decoded token rollouts: \[ \mathbb{E}_{X,Y,Z}\left[(\phi(Z)-Y)^2\right]. \] Thus all token strings with the same decoded value are interchangeable to LM-RLOO. If \(\phi(z)=y\) exactly, the reward is zero regardless of whether \(z\) is the canonical P10 string.

LM-MaxRL

LM-MaxRL replaces the raw squared-error reward by a normalized Gaussian likelihood score. Let \(\tau>0\) denote score_std. For a rollout \(z\), define \[ s_\tau(y,z) := \exp\left(-\frac{(\phi(z)-y)^2}{2\tau^2}\right) \in (0,1]. \] This is the Gaussian observation likelihood \(\mathcal{N}(y;\phi(z),\tau^2)\) divided by its supremum \((\sqrt{2\pi}\tau)^{-1}\), so the maximum possible score is one. For one example, the marginal normalized likelihood under the LM policy is \[ S_{\theta,\tau}(x,y) := \mathbb{E}_{Z\sim q_{\theta,T}(\cdot\mid x)} [s_\tau(y,Z)]. \]

The degree-\(D\) MaxRL target is the truncated log-likelihood objective \[ J_D(\theta) = \mathbb{E}_{X,Y} \left[ -\sum_{k=1}^{D} \frac{(1-S_{\theta,\tau}(X,Y))^k}{k} \right]. \] As \(D\to\infty\) this becomes \[ J_\infty(\theta) = \mathbb{E}_{X,Y}\left[\log S_{\theta,\tau}(X,Y)\right]. \]

The sampled implementation uses the same leave-one-out MaxRL estimator described in MaxRL gradient estimator details. For sampled scores \(s_j=s_\tau(y,Z_j)\), define complements \(a_j=1-s_j\). The leave-one-out weight for rollout \(j\) is \[ \omega_j = \sum_{k=0}^{D-1} \frac{e_k((a_i)_{i\ne j})}{\binom{R-1}{k}}, \] where \(e_k\) is the \(k\)-th elementary symmetric polynomial and \(e_0=1\). The current LM-MaxRL recipe always subtracts a rollout baseline: \[ s^{\mathrm{eff}}_j = \frac{R}{R-1}(s_j-\bar s), \qquad \bar s := \frac{1}{R}\sum_{i=1}^{R}s_i. \] The surrogate loss is \[ \widehat{\mathcal{L}}_{\mathrm{LM\mbox{-}MaxRL}} = -\frac{1}{BR} \sum_{b=1}^{B}\sum_{j=1}^{R} \omega_{b,j}s^{\mathrm{eff}}_{b,j} \log q_{\theta,T}(Z_{b,j}\mid x_b), \] with the weights detached. By default, the implementation uses \(D=R\) unless a separate degree is provided.

Optimization targets and limits

The CE and LM-RL methods can share a decoder and tokenizer while optimizing different population quantities:

Method Population target What is treated as correct?
CE pretraining Maximize \(\mathbb{E}[\log q_\theta(c(Y)\mid X)]\) token by token Only the canonical token string \(c(Y)\)
LM-RLOO Maximize \(\mathbb{E}[-(\phi(Z)-Y)^2]\) for \(Z\sim q_{\theta,T}(\cdot\mid X)\) Any rollout whose decoded number is close to \(Y\)
LM-MaxRL Maximize \(J_D\) or, as \(D\to\infty\), \(\mathbb{E}[\log \mathbb{E}_{Z\sim q_{\theta,T}(\cdot\mid X)}s_\tau(Y,Z)]\) Any rollout with high Gaussian score after decoding
NoteShared decoder, different target

CE, LM-RLOO, and LM-MaxRL can use the same P10 decoder while learning from different signals. CE concentrates probability on a canonical string. LM-RLOO and LM-MaxRL score decoded scalar values, so token strings that parse to the same useful number are equivalent for the rollout objective.

CE has no training rollout count or score standard deviation. As the evaluation sample count grows, its reported median prediction converges to the median of \(\phi(Z)\) under the learned decoder distribution. This affects evaluation Monte Carlo error while leaving the CE training target unchanged.

As the number of LM-RL training rollouts \(R\) grows, LM-RLOO converges to the exact policy gradient of \(J_{\mathrm{LM\mbox{-}RLOO}}\). The leave-one-out baseline leaves the population target unchanged and changes estimator variance. LM-MaxRL converges to the gradient of the degree-\(D\) MaxRL target when \(D\) is fixed. Under the default choice \(D=R\), sending \(R\to\infty\) also sends \(D\to\infty\), so the target approaches the log marginal score \(J_\infty\).

The score_std limit only applies directly to LM-MaxRL and is separate from the rollout sampling temperature. LM-RLOO has no score_std hyperparameter in the current implementation. For LM-MaxRL:

  • As \(\tau\to 0\), \(s_\tau(y,z)\) approaches an indicator of exact numeric equality \(\phi(z)=y\). If \(y\) is exactly representable, the limiting objective rewards the total probability of all exact representations \(\sum_{z:\phi(z)=y}q_\theta(z\mid x)\), including non-canonical strings. If \(y\) falls between representable decoded values, the signal concentrates on the nearest grid points and can become extremely sparse in finite rollouts.
  • As \(\tau\to\infty\), \(s_\tau(y,z)=1-(\phi(z)-y)^2/(2\tau^2)+O(\tau^{-4})\). Therefore \(\log S_{\theta,\tau}(x,y)\) is \(-\mathbb{E}_{Z}[(\phi(Z)-y)^2]/(2\tau^2)+O(\tau^{-4})\) up to constants. The target becomes expected decoded MSE, and the gradient scale vanishes like \(\tau^{-2}\).

For LM-RLOO, introducing an artificial reward scale \(-(\phi(z)-y)^2/(2\tau^2)\) would leave the optimum unchanged for any finite \(\tau>0\) and would simply rescale the gradient. The current code fixes this scale implicitly by using \(-(\phi(z)-y)^2\).

Regression-head model

The regression-head methods use a deterministic scalar predictor \[ g_\theta(x) \in \mathbb{R}. \] The architecture is a T5Gemma encoder, a learned one-token query passed through a transformer decoder over the encoder memory, and a linear value head. In code, the model predicts from the decoded query state: \[ g_\theta(x) = w^\top h_\theta(x) + b. \]

This architecture removes the numeric tokenizer from the output side. The model is judged directly in the same scalar space as the target variant being trained: raw bytes for the raw task, or normal scores for the quantile-normalized task.

SL-MSE - direct scalar regression

The supervised regression baseline minimizes the same squared error used by the primary evaluation: \[ \mathcal{L}_{\mathrm{SL\mbox{-}MSE}}(\theta) = \mathbb{E}\left[(g_\theta(X)-Y)^2\right]. \]

For a minibatch, \[ \widehat{\mathcal{L}}_{\mathrm{SL\mbox{-}MSE}} = \frac{1}{B}\sum_{b=1}^{B} (g_\theta(x_b)-y_b)^2. \]

This is the cleanest reference objective: if the evaluation target is MSE, then SL-MSE optimizes it directly. It uses no rollouts, likelihood temperatures, tokenization choices, or policy-gradient estimator.

RLOO - Gaussian rollout policy with leave-one-out rewards

RLOO turns the scalar predictor into the mean of a Gaussian rollout policy: \[ Z_j \sim \pi_\theta(\cdot \mid x) = \mathcal{N}(g_\theta(x), \sigma^2), \qquad j=1,\dots,R. \]

The reward is negative squared error against the scalar target: \[ r_j = -(Z_j - y)^2. \]

The leave-one-out advantage is \[ A_j = r_j - \frac{1}{R-1}\sum_{k\ne j}r_k = \frac{R}{R-1}(r_j-\bar r), \qquad \bar r := \frac{1}{R}\sum_{k=1}^{R}r_k. \]

The score-function surrogate is \[ \widehat{\mathcal{L}}_{\mathrm{RLOO}} = -\frac{1}{BR}\sum_{b=1}^{B}\sum_{j=1}^{R} A_{b,j}\, \log \pi_\theta(Z_{b,j}\mid x_b), \] with the sampled advantages detached.

The leave-one-out baseline is unbiased because it depends only on peer rollouts for the current example. In the population limit, \[ \mathbb{E}_{Z\sim\mathcal{N}(g_\theta(x),\sigma^2)} [-(Z-y)^2] = -(g_\theta(x)-y)^2 - \sigma^2. \] The extra \(\sigma^2\) term is independent of \(\theta\), so maximizing expected RLOO reward has the same optimum and gradient direction as minimizing scalar MSE. Finite \(R\) changes the variance of the gradient estimator while preserving the population target.

MaxRL - likelihood-weighted rollout estimator

MaxRL uses the same Gaussian rollout policy, \[ Z_j \sim \mathcal{N}(g_\theta(x),\sigma^2), \] and scores each rollout by a Gaussian observation likelihood of the target: \[ \ell_y(z) = \mathcal{N}(y; z, \sigma^2). \]

The supremum of this one-dimensional likelihood is \[ L = \frac{1}{\sqrt{2\pi}\sigma}, \] so the normalized likelihood is \[ \sigma_j := \frac{\ell_y(Z_j)}{L} = \exp\left(-\frac{(Z_j-y)^2}{2\sigma^2}\right) \in (0,1]. \]

For one example, define the marginal normalized likelihood \[ \sigma_\theta(x,y) := \mathbb{E}_{Z\sim\pi_\theta(\cdot\mid x)} [\sigma_y(Z)]. \] The degree-\(M\) MaxRL objective is the same truncation used in MaxRL gradient estimator details: \[ J_M(\theta) = -\sum_{k=1}^{M} \frac{(1-\sigma_\theta)^k}{k}. \] As \(M\to\infty\), this approaches \[ J_\infty(\theta) = \log \sigma_\theta. \]

The sampled estimator forms leave-one-out weights from the peer complements \(a_i = 1-\sigma_i\). For rollout \(j\), \[ \omega_j = \sum_{k=0}^{M-1} \frac{ e_k((a_i)_{i\ne j}) }{ \binom{R-1}{k} }, \] where \(e_k\) is the \(k\)-th elementary symmetric polynomial. With baseline subtraction, the effective normalized likelihood term is \[ \sigma^{\mathrm{eff}}_j = \frac{R}{R-1}(\sigma_j-\bar\sigma), \qquad \bar\sigma := \frac{1}{R}\sum_{i=1}^{R}\sigma_i. \] The policy-gradient surrogate is \[ \widehat{\mathcal{L}}_{\mathrm{MaxRL}} = -\frac{1}{BR}\sum_{b=1}^{B}\sum_{j=1}^{R} \omega_{b,j}\sigma^{\mathrm{eff}}_{b,j} \log \pi_\theta(Z_{b,j}\mid x_b), \] with the score weights detached.

In the exact Gaussian limit, MaxRL also reduces to MSE. The convolution identity gives \[ \mathbb{E}_{Z\sim\mathcal{N}(g_\theta(x),\sigma^2)} [\mathcal{N}(y;Z,\sigma^2)] = \mathcal{N}(y;g_\theta(x),2\sigma^2), \] so \[ \log \sigma_\theta(x,y) = -\frac{(g_\theta(x)-y)^2}{4\sigma^2} + \mathrm{const}. \] Thus the infinite-rollout MaxRL objective is a positive rescaling of negative MSE plus a constant. As with RLOO, the finite-rollout estimator is the interesting object: it changes how noisy or selective the update is while the ideal scalar target remains MSE in this Gaussian setup.

Evaluation

This writeup focuses on CDSS metrics. The primary keys are

Metric key Meaning
eval-core/mse/space/CDSS pooled CDSS mean squared error
eval-core/mae/space/CDSS pooled CDSS mean absolute error
eval-core/spearman/space/CDSS pooled CDSS Spearman rank correlation

Evaluation set construction

The eval set is balanced by CDSS language. For each cdss_language/<language> group, the cache builder keeps at most eval_cap_per_group examples; in the current Modal recipes this cap is 256. Languages with at least 256 valid CDSS examples enter the evaluation. Thus, if \(|\mathcal{L}|\) languages survive the threshold, the pooled CDSS eval set contains exactly \[ 256 \cdot |\mathcal{L}| \] examples, with the same number of examples from each retained language.

Selection is deterministic: examples are ordered by a stable hash of their identifier, then capped within language. Each retained row is assigned both its auxiliary language group, such as cdss_language/Python, and the pooled space/CDSS group.

The pooled CDSS metric treats all selected CDSS eval examples as one population. For MSE, with selected CDSS pairs \((y_i,\hat y_i)\), \[ \widehat{\mathrm{MSE}}_{\mathrm{CDSS}} = \frac{1}{N}\sum_{i=1}^{N}(\hat y_i-y_i)^2. \] MAE is the same pooled average with absolute error, and Spearman is computed once over the pooled CDSS target and prediction vectors.

Language-mean metrics shift the estimand. The auxiliary cdss_language/<language> groups first compute a metric within each language. Then eval-core/<metric>/space/CDSS_language_mean averages those language scores equally: \[ \widehat{m}_{\mathrm{language\ mean}} = \frac{1}{|\mathcal{L}|} \sum_{\ell\in\mathcal{L}} \widehat{m}_\ell. \]

The decoder-LM and regression-head routes produce predictions differently before metrics are computed:

  • CE pretraining, LM-RLOO, and LM-MaxRL sample numeric decodes and use the per-example median decoded value as the prediction.
  • Regression-head methods produce one deterministic scalar prediction \(g_\theta(x)\).

After that, all methods are evaluated with the same target/prediction metric code.
